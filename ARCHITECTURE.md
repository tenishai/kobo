# kobo — repo card

WHAT: the agent assembly room. A web UI + API where a signed-in person composes an agent (persona, skills, group), clicks Create, and the room provisions a running daedalus agent on gojira; then chat/teach it, wire Slack, and govern who (people and other agents) may reach it.
STATE: main; tenish-kobo (the API package) 0.3.10 and kobo-ui 0.3.10 (both move with each release); alpha, deployed, very active (in 0.3.10: activity at a glance, picker offers connected accounts only). Design record per arc in docs/superpowers/.
STACK: Python >=3.12, FastAPI + uvicorn, SQLAlchemy >=2,<2.1 (SQLite default, Postgres for multi-replica), alembic, pydantic v2, httpx, PyJWT, `mcp>=1.15,<2` (FastMCP 1.x surface), prometheus-client, OpenTelemetry (env-gated). UI: Svelte 5 + Vite + TanStack Query, hand-rolled router (ui/src/lib/router.svelte.ts), NOT SvelteKit. Shells out to `git`, `gh`, `kubectl`, `gcloud` (baked into the image, Dockerfile).
ENTRY:
- API app factory: api/kobo_api/main.py `build_default_app()` (real wiring: config → org.yaml merge → engine → `sweep_interrupted` → `Clients.real` → Slack-store probe → boot dispatch-pairs sync) and `create_app()` (all routes are closures inside this one function; tests call it with fakes)
- container: Dockerfile (UI build stage + python runtime, UID 1001) → docker/entrypoint.sh runs `alembic upgrade head` then `uvicorn --factory kobo_api.main:build_default_app` on :8080
- dev: `make -C api install && make -C api run` (:8100); `make -C ui dev` (:5173, proxies /api)
- bootstrap CLI: `python -m kobo_api.bootstrap` (api/kobo_api/bootstrap.py; stands up an org's config repo/buckets/personas)
- MCP server: /mcp + /oauth + /.well-known, mounted only when `config.mcp_enabled` (api/kobo_api/mcp/mount.py)
- role: `KOBO_ROLE` = `all` (default) | `api` (serves, enqueues) | `worker` (claims and runs pipelines, sweeps, nightly pass); see docs/arch/provisioning.md. health.py probes ready agents' Deployments once a minute and the UI shows Down over Ready when the pods are not running.
- agent-facing broker lane: /broker/agents/{name}/github-token, /jira/* (api/kobo_api/main.py, api/kobo_api/pr_broker.py; auth = the agent's cabal colleague JWT)
- config: YAML via `KOBO_CONFIG` or ./config.local.yaml (api/kobo_api/config.py `Config.load`), then org.yaml from the org config repo merged over it at boot (api/kobo_api/org.py `load_org_config`, keys in `ORG_KEYS`) and again on `POST /api/admin/org/reload`. `Config` and `MCPConfig` are `extra="forbid"`: an unknown key fails boot; retired keys are dropped with a warning (`RETIRED_CONFIG_KEYS`, `org.RETIRED_ORG_KEYS`). Every boot logs the auth regime (`auth_regime`). Env secrets: CABAL_OPERATOR_TOKEN, OKTA_API_TOKEN, the MCP JWT signing key (env name from `mcp.jwt_key_env`, default KOBO_MCP_JWT_KEY), and the OAuth client secret (env name from `mcp.oauth_client_secret_env`, default KOBO_MCP_GOOGLE_CLIENT_SECRET). Env switch, not a secret: OTEL_EXPORTER_OTLP_ENDPOINT (tracing is on only when set).

- (uncarded) api/kobo_api/room_services.py — Room services (#284; shown as the Slack and GitHub rows of the admin Integrations table since #304, and `GET /api/whoami` carries `github_available` so an agent's Repositories card greys out until an admin sets GitHub up): the Slack config-token pair and the GitHub app for pull requests held by the room itself, one Kubernetes Secret per service in `room_namespace` (or the pod's own), read live with a 5 s cache; `slack_client(clients)` resolves the Slack client per request (room-held pair first, then `Clients.slack`, the deployment client, which stays None when nothing is configured), `RoomServices.github_app()` is what the PR broker mints with (room first, then `pr_app_*`), `slack_configured(clients)` is the one Slack gate. Namespace = `room_namespace` or the pod's own file, never ambient kubectl state. Served by `GET/PUT/DELETE /api/admin/room-services[/{slack|github}]`, admin-gated, values never echoed, 409 when the room has no namespace to store in.

DEPS: no Python imports of sibling repos (daedalus only via `pytest.importorskip` in tests/test_wire_bundle.py). Runtime contracts, all over the network or git:
- gojira: HTTP `/api/v1/apps` create/status/provision/delete + `/healthz` (clients.py `HttpxGojiraClient`); kobo edits each agent repo's `gojira.yaml` and `k8s/base/kustomization.yaml`.
- daedalus: bundle schema vendored verbatim at api/kobo_api/vendor/bundle.schema.json; agent images `FROM` `config.runtime_image` (the daedalus runtime).
- cabal: admin API (directory, relay, token mint/revoke, dispatch-pairs, conversations, SSE) with operator bearer; kobo is the policy owner.
- sero: machine-lane secrets, auth = pod's Google ID token (sero.py).
- liminal: `liminal_url` baked into each bundle's tools block; techne: each agent's memory store on a PVC (runtime side; kobo never imports techne).
- GitHub (gh CLI + GitHub App), Okta (groups/people), Vertex (names, persona drafts, avatars), GCS (catalogs), Slack (manifest API).
HEALTH: API tests live under api/tests (pytest, `-n auto`; each test owns its SQLite file; `make -C api test` locally runs serial). UI: vitest + svelte-check. CI (.github/workflows/ci.yml): `api-tests` as three shards, each every third test file in sorted order on its own runner pod (2026-10-30: the self-hosted pod has 3.5 cores, so one job took six minutes), the architecture-card check on shard 1 only, `ui` (build, check, test), `migrations` (alembic to head on real Postgres 16 + scripts/schema_tripwire.py), and `test-lifecycle` (TESTING.md: scaffold tests must not reach a PR). CI builds and publishes NO image (since 2026-10-02): an operator builds one from a commit and rolls it where it runs. Ruff is NOT in CI. No branch protection: CI reports, never blocks. A `dockerfile` job lints both Dockerfiles with `docker buildx build --check` (ghcr login first: the base image is private); the image itself is built only by release.yml (2026-10-29).
GOTCHAS:
- CI installs with `uv sync --locked` against the committed `api/uv.lock` (2026-10-05); a
  drifted lock fails the job instead of silently resolving. The same job runs
  `scripts/check_arch_cards.py`, so a seam changed without its card fails CI (2026-10-05). The Dockerfile's `pip install ./api`
  is still unlocked, which is how SQLAlchemy 2.1.1 slipped in and crashed boot on 2026-09-25, so
  runtime floors and ceilings are still pinned in pyproject (comment there).
- Tests run on SQLite; production multi-replica runs Postgres. A model change needs an alembic migration or the pod crashloops; CI's `migrations` job is the only thing that catches it. `init_db` (`create_all`) still runs at boot on both backends.
- main.py is very large and every route is a closure inside `create_app`; helpers you need (`_visible_agents`, `_is_admin`, gates) are module-level above it. Don't add a second visibility check per route.
- "team" ≠ "group": `Agent.team` is the skills-catalog axis, `Agent.group_name` is the ACL namespace (composer.py `BundleSpec` comment). `SHARED_GROUP = "shared"` is the commons: visible to all, but NOT implicitly paired.
- Three agent kinds (kinds.py): `composed` (room owns the repo, pushes), `connected` (team's own repo; room proposes by PR, no switchboard identity, no pairs) and `directory` (composed into `<directory_root>/<agent>/` under `delivery_backend: directory`; no repo, no image, destroy removes the folder and the listing). Code tests `!= KIND_CONNECTED` (or `is_connected`), so a future kind behaves as composed, with one deliberate exception: destroy.py `_destroy_repo` tests `!= KIND_COMPOSED`, so an unknown kind is treated as not composed there and its repository is left alone.
- CORS is `allow_origins=["*"]` unconditionally (main.py `create_app`), not only in dev; the perimeter is IAP, not CORS.
- Several integrations are "absent = off": cabal needs cabal_url + agent_endpoint_template + CABAL_OPERATOR_TOKEN; Okta groups need OKTA_API_TOKEN + okta_domain + groups; sero needs all three sero_* keys; the Noto deep link needs both noto_url and noto_project (`/api/catalog/observability` returns neither when one is missing); MCP needs `mcp.oauth_client_id`; the tool gateway block needs `liminal_url`; live gateway grants and the Activity view need `liminal_admin_url` and the switchboard (`liminal_admin.build_liminal_admin`); the admin panel needs `admin_panel: true`.
