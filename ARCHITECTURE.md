# kobo — repo card

WHAT: the agent assembly room. A web UI + API where a signed-in person composes an agent (persona, skills, group), clicks Create, and the room provisions a running daedalus agent on gojira; then chat/teach it, wire Slack, and govern who (people and other agents) may reach it.
STATE: main; tenish-kobo (the API package) 0.3.76 and kobo-ui 0.3.76 (both move with each release); alpha, deployed, very active (in 0.3.76: **Every repository, Read only** on an agent's GitHub step (`{"all": true}` on the repositories PUT, the child's `all_repositories`, bab 0.4.26 keeping it to Read alone), and a connected agent's **Create Slack app** goes on to the install even when its repository's pull request has to wait; in 0.3.75: what a permission opens on the gateway comes from the handlers' own cards (`GET /admin/cards`, liminal 0.10.0; `gateway_lane.Lanes`, the last read in `gateway_cards`, every part a card's lane named in `gateway_managed`), the room's own targets keeping their lanes; and an agent's rules are one Guardrails list on the Harness tab (`bundle/guardrails.md`, `GET/PUT /api/agents/{name}/guardrails`, provenance in `guardrail_rules`, **It broke this**, a persona's rules as starter guardrails), off until the deployment config's `guardrails` is on with a runtime that reads the file; in 0.3.74: an agent's Slack row says what another app's @-mention may do, carried as `SLACK_BOT_MENTIONS` on the wake route (`knowledge` unset, `full`, `off`), and has a box that writes the runtime's `slack_read` block into a room-built agent's bundle (`PUT /api/agents/{name}/slack/reading`, `composer.update_agent_yaml_slack_read`, `delivery.redeliver` for a save whose delivery failed); a persona drafted from a document keeps its working detail; in 0.3.73: **Build your own persona** is one form that also edits (`PUT /api/personas/{id}`, text the form can read back only), every new or edited persona meets a floor and the same cleaners (`personas.check_substance`, `clean_who`, `house_body`, `clean_rule`), a new persona is filed under its maker's group, and the persona list in **Create agent** has its group pills above it and lists a search's matches under each group's name; in 0.3.72: **Create Slack app** goes straight on to Slack's install page with the link the create route already returns, one press instead of two; Slack is wired as `optional: true` wherever the room writes it, so an image-built agent whose room-made app is not installed yet starts without it; and **Image build** reruns once a successful platform build that ended before the agent was created, so connecting a repository again after a destroy deploys it; in 0.3.71: connecting a repository hands its deploy files over, so the platform is told `handed_over` and merges its own pull requests and the room merges the ones it opens (`agent_env.merge_ours`), a merge GitHub refuses being the only wait left; and every agent runs as the room's account `agent-<name>`, a connected one included, the wiring moving a repository off an account of its own; in 0.3.70: Okta is an integration, one domain and API token the room checks and the gateway's `okta` handler reads from a synced Secret, with two levels in `gateway_lane.py` and no gateway target to write or remove (`admin_integrations._connect_okta`, `HANDLER_AUTHS`); in 0.3.69: a connected repository keeps the service account it already names, recorded on the agent as `agents.service_account` and read through `steps.service_account_of`, where the wiring step used to refuse it; in 0.3.68: a connected agent's page has the same places as any agent's: it opens on a tab, has Edit details with its owner's one line and its destroy, and has a Chat tab that works once its code answers the switchboard, with a fourth line saying what chat waits on; in 0.3.67: connecting a repository asks its team for one pull request where it has no deploy files (the room's wiring rides the deploy service's setup request as `seed`), Slack asks a connected agent's team for none, and a connected agent's page says where it stands in three lines; in 0.3.66: an agent answers its slash command only where it has been added, and one box on the Slack row, carried as `SLACK_COMMAND_PUBLIC`, lets it answer in any public channel; in 0.3.65: an agent in Slack can offer choices as buttons, take a slash command that is its own name, post in a public channel without an invite, pin and bookmark, with clicks and commands arriving at two new relay addresses; in 0.3.64: a reaction with an emoji its owner named wakes an agent in Slack, one field on the Slack row, carried as `SLACK_WAKE_EMOJI`; in 0.3.63: an assistant can read and ask for an agent's access, pick its repositories, make and update its Slack app and read its activity, through eight new MCP tools that call the page's own routes; a room-made Slack app can post files and read emoji and groups, and an installed one is updated with one approval; in 0.3.62: a connected agent is wired like one the room builds). Design record per arc in docs/superpowers/. Adding a vendor end to end (catalogue, minter, vendor-side switches, connect form, live gateway target, lane + bundle allow, skills, guide) is docs/adding-a-vendor.md; read it before touching any of those.
STACK: Python >=3.12, FastAPI + uvicorn, SQLAlchemy >=2,<2.1 (SQLite default, Postgres for multi-replica), alembic, pydantic v2, httpx, PyJWT, `mcp>=1.15,<2` (FastMCP 1.x surface), prometheus-client, OpenTelemetry (env-gated). UI: Svelte 5 + Vite + TanStack Query, hand-rolled router (ui/src/lib/router.svelte.ts), NOT SvelteKit. Shells out to `git`, `gh`, `kubectl`, `gcloud` (baked into the image, Dockerfile).
ENTRY:
- API app factory: api/kobo_api/main.py `build_default_app()` (real wiring: config → org.yaml merge → engine → `sweep_interrupted` → `Clients.real` → Slack-store probe → service-row fold (`room_credentials.migrate_service_rows`, kobo#377) → boot dispatch-pairs sync) and `create_app()` (all routes are closures inside this one function; tests call it with fakes)
- container: Dockerfile (UI build stage + python runtime, UID 1001) → docker/entrypoint.sh runs `alembic upgrade head` then `uvicorn --factory kobo_api.main:build_default_app` on :8080
- dev: `make -C api install && make -C api run` (:8100); `make -C ui dev` (:5173, proxies /api)
- bootstrap CLI: `python -m kobo_api.bootstrap` (api/kobo_api/bootstrap.py; stands up an org's config repo/buckets/personas)
- MCP server: /mcp + /oauth + /.well-known, mounted only when `config.mcp_enabled` (api/kobo_api/mcp/mount.py)
- Slack relay: /slack/relay/{relay_id} (+ `/actions` for clicks and `/commands` for the agent's slash command, kobo#484: signed forms, answered with an empty 200, forwarded to the agent's `/slack/events` as JSON) + /slack/oauth/callback (api/kobo_api/slack_relay.py, router included in `create_app`), the public no-IAP way Slack's events reach an agent whose app the room made (kobo#371); 404 unless the org key `slack_relay` is on
- role: `KOBO_ROLE` = `all` (default) | `api` (serves, enqueues) | `worker` (claims and runs pipelines, sweeps, nightly pass); see docs/arch/provisioning.md. health.py probes ready agents' Deployments once a minute and the UI shows Down over Ready when the pods are not running.
- agent-facing brokers: none. The GitHub token broker (`/broker/agents/{name}/github-token`, `/api/agents/{name}/repo-access`, `/api/repo-access*`, the three MCP repo-access tools, the composed `github` sidecar) retired 2026-11-01 (kobo#365), and the Jira read lane (`/broker/agents/{name}/jira/*`, jira_broker.py, pr_broker.py, the `jira_*` config keys) on 2026-11-04; agents reach both vendors through the tool gateway. See github_access below.
- config: YAML via `KOBO_CONFIG` or ./config.local.yaml (api/kobo_api/config.py `Config.load`), then org.yaml from the org config repo merged over it at boot (api/kobo_api/org.py `load_org_config`, keys in `ORG_KEYS`) and again on `POST /api/admin/org/reload`. `Config` and `MCPConfig` are `extra="forbid"`: an unknown key fails boot; retired keys are dropped with a warning (`RETIRED_CONFIG_KEYS`, `org.RETIRED_ORG_KEYS`). Every boot logs the auth regime (`auth_regime`). Env secrets: CABAL_OPERATOR_TOKEN, OKTA_API_TOKEN, the MCP JWT signing key (env name from `mcp.jwt_key_env`, default KOBO_MCP_JWT_KEY), and the OAuth client secret (env name from `mcp.oauth_client_secret_env`, default KOBO_MCP_GOOGLE_CLIENT_SECRET). Env switch, not a secret: OTEL_EXPORTER_OTLP_ENDPOINT (tracing is on only when set).

GOTCHAS:
- CI installs with `uv sync --locked` against the committed `api/uv.lock` (2026-10-05); a
  drifted lock fails the job instead of silently resolving. The same job runs
  `scripts/check_arch_cards.py`, so a seam changed without its card fails CI (2026-10-05). The Dockerfile's `pip install ./api`
  is still unlocked, which is how SQLAlchemy 2.1.1 slipped in and crashed boot on 2026-09-25, so
  runtime floors and ceilings are still pinned in pyproject (comment there).
- Tests run on SQLite; production multi-replica runs Postgres. A model change needs an alembic migration or the pod crashloops; CI's `migrations` job is the only thing that catches it. `init_db` (`create_all`) still runs at boot on both backends.
- main.py is very large and every route is a closure inside `create_app`; helpers you need (`_visible_agents`, `_is_admin`, gates) are module-level above it. Don't add a second visibility check per route.
- "team" ≠ "group": `Agent.team` is the skills-catalog axis, `Agent.group_name` is the ACL namespace (composer.py `BundleSpec` comment). `SHARED_GROUP = "shared"` is the commons: visible to all, but NOT implicitly paired.
- Three agent kinds (kinds.py): `composed` (room owns the repo, pushes), `connected` (team's own repo; room proposes by PR, no switchboard identity, no pairs) and `directory` (composed into `<directory_root>/<agent>/` under `delivery_backend: directory`; no repo, no image, destroy removes the folder and the listing). Code tests `!= KIND_CONNECTED` (or `is_connected`), so a future kind behaves as composed, with one deliberate exception: destroy.py `_destroy_repo` tests `!= KIND_COMPOSED`, so an unknown kind is treated as not composed there and its repository is left alone.
- CORS is `allow_origins=["*"]` unconditionally (main.py `create_app`), not only in dev; the perimeter is IAP, not CORS.
- Several integrations are "absent = off": cabal needs cabal_url + agent_endpoint_template + CABAL_OPERATOR_TOKEN; Okta groups need OKTA_API_TOKEN + okta_domain + groups; sero needs all three sero_* keys; the Noto deep link needs both noto_url and noto_project (`/api/catalog/observability` returns neither when one is missing); MCP needs `mcp.oauth_client_id`; the tool gateway block needs `liminal_url`; live gateway grants and the Activity view need `liminal_admin_url` and the switchboard (`liminal_admin.build_liminal_admin`); the admin panel needs `admin_panel: true`.
