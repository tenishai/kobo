# P2d — Avatars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an agent a face — one click on the detail page generates an avatar from the agent's persona via a Vertex model-garden image endpoint, stores it as `bundle/avatar.png` in the agent's repo (the bundle of record), and shows it across the room.

**Architecture:** Discovery (ledgered, report in `.superpowers/sdd/p2d-discovery.md`) locked the endpoint: `gemini-2.5-flash-image` (GA) via `:generateContent`, v1, region `us-central1`, on the shared model-access project — verified working today with a real generation, no enabling required (the Imagen family is entitlement-blocked here and being retired this month; Google's own migration path points at this model). A new `ImageClient` (httpx, ADC bearer token via the existing gcloud-token idiom if one exists — else `google.auth.default`) returns PNG bytes; an avatar module derives a square-avatar prompt from the persona, commits `bundle/avatar.png` via the established clone/commit/local_head path, and stores a base64 display copy on the agent row so the room can render lists without cloning repos. Delivery of the repo commit rides the P2b machinery unchanged (an avatar rebuild is a normal delivery; the runtime ignores the file). Regeneration is an idempotent overwrite — same one-click, new face.

**Tech Stack:** unchanged (FastAPI/pytest; Svelte 5/vitest).

## Global Constraints

- Never the employer's name or work-app name in any tracked file; zero infra vocabulary in UI copy (no "endpoint", "Vertex", "model garden", "repo", "commit" — copy speaks of giving the agent a face/picture).
- TDD; `make -C api check` and `PATH="/opt/homebrew/bin:/usr/local/bin:$PATH" make -C ui check` fully green before every commit; **git add only named files**.
- Config additions live in `config.py` with neutral example values in `config.example.yaml`; real values only in gitignored `config.local.yaml` (avatar_model `gemini-2.5-flash-image`, avatar_location `us-central1`, vertex project reuses the existing `vertex_project` field).
- The avatar is display-only: the runtime never reads it; the DB copy is a cache of the repo file, never the record.
- Generated images: request exactly one square image; enforce a response-size sanity cap (reject > 4 MiB with a plain-language error) before storing anything.
- Do not touch the Slack app icon — Slack has no icon API; the SlackPanel's existing "add a picture later in Slack's settings" note already covers it.

**Interfaces:**
```python
class ImageClient(Protocol):
    def generate(self, prompt: str) -> bytes:
        """Generate one square PNG from `prompt`; raise ClientError on failure."""

class VertexImageClient:
    def __init__(self, project: str, location: str, model: str, http_client=None, token_provider=None): ...
    # POST https://{location}-aiplatform.googleapis.com/v1/projects/{project}/locations/{location}/publishers/google/models/{model}:generateContent
    # body: {"contents":[{"role":"user","parts":[{"text": prompt}]}],
    #        "generationConfig":{"responseModalities":["TEXT","IMAGE"]}}
    # auth: Bearer token from token_provider() — default provider shells `gcloud auth print-access-token`
    #   through CommandRunner IF the codebase lacks an existing google-auth idiom (check first; the
    #   pipeline's gcloud client may already own token acquisition — reuse whatever exists, disclose).
    # reply: first candidate part carrying inlineData {mimeType, data(base64)} -> decode, return bytes.
    #   No image part / ok-but-blocked (safety) -> ClientError("the picture didn't come through — try again")
    #   non-200 or malformed JSON -> ClientError (wrap like _post_task does; never include the prompt in errors... prompt is not secret — include it only in logs, not user-visible bodies).
```
- `Clients` gains `image: ImageClient` wired from config (always constructible — no optional gating; the vertex fields already exist).

- Tests: request shape via MockTransport (URL, auth header from a fake token provider, body exact); happy decode from a canned inlineData reply; safety-blocked/no-image → ClientError; non-200 → ClientError; oversize response guard if placed here (see Task 2 — put the cap where the bytes are first held; disclose placement).
