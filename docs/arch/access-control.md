# access-control — who may see and change which agent (UI, MCP, broker)

WHAT / SEAM: identity is ONE attribute, `request.state.iap_email`, and every decision is made by a handful of module-level helpers in api/kobo_api/main.py (above `create_app`; they are not anchored here because main.py changes on nearly every commit, so re-check them by name): `_is_operator`, `_is_admin`, `_is_reader`, `_visible_agents`, `_visible_agent_or_404`, `_owner_or_operator_or_403`, `_decider_or_403`, `_operator_block` / `_admin_operator_block` / `_convert_operator_block` / `_repo_access_operator_block` / `_slack_operator_block`, `_group_choice_block`.
Three entry lanes, one set of gates:
- Browser/UI: `IapMiddleware` (iap.py) verifies `x-goog-iap-jwt-assertion` against Google's JWKS (12h cache) and `config.iap_audience`, stamps `iap_email`, and returns 401 otherwise. Only active when `iap_audience` is set.
- MCP: `/oauth/*` is kobo's own OAuth 2.1 AS (mcp/oauth_as.py: Google OIDC, Workspace-domain gate, PKCE, dynamic registration); access tokens are kobo JWTs (mcp/jwt.py, key env named by `mcp.jwt_key_env`, default `KOBO_MCP_JWT_KEY`, `sub` = email); refresh tokens rotate in families (mcp/refresh_tokens.py; reuse revokes the family; a family ends after `FAMILY_MAX_AGE`, 30 days). An authorization code is spent once (`mcp_redeemed_codes`, keyed by the code's jti; a replay revokes the first exchange's family, #196). `POST /api/admin/mcp/revocations` cuts a person off (`mcp_revocations`): their families die and `_KoboTokenVerifier` refuses access tokens issued before the instant, behind a 30 s per-process cache (#197). `mcp/authz.py room_request(app, email)` builds a synthetic Request so tools call the SAME main.py gates; write tools call the route functions themselves (mcp/tools/write.py). The synthetic request also carries `state.audit_source = "mcp"`, which `kobo_api.audit.record` reads so a row written through an assistant's connection says so (#316).
- Agents: `/broker/agents/{name}/*` authenticates the agent's cabal colleague JWT (pr_broker.py `verify_agent_token`: issuer cabal-core, sub `agent:<name>`, and `iat` no earlier than `Agent.pass_minted_at`, the instant `colleagues.deliver_pass` last minted the pass, so a re-wire ends an older pass here too, #199; one cached `PyJWKClient` per switchboard URL), then mints a GitHub token scoped to that agent's APPROVED `RepoAccess` rows and PR-only permissions.
OPS / FLOW: middleware order (Starlette runs last-added first): `HttpsOnlyMiddleware` → `IapMiddleware` → CORS → metrics recorder (metrics.py `install`, added first, so it runs innermost) → routes. IAP exemptions: `EXEMPT_PATHS` {/api/healthz, /metrics} and `EXEMPT_PREFIXES` (/mcp, /oauth, /.well-known, /broker), matched on the normalized path at segment boundaries. `HTTPS_ONLY_PREFIXES` (/mcp, /oauth, /.well-known) answer `X-Forwarded-Proto: http` with a 308 to https (GET/HEAD) or a refusal, before any credential is read; /broker is in-cluster only, so it is exempt from that check.
Visibility (`_visible_agents`, in order): IAP off → all; admin → all; reader → all (read only); no group resolver → all; else owned (`created_by`) ∪ granted (`AgentUserGrant`, either role) ∪ commons (`group_name == "shared"`) ∪ agents in the caller's resolved groups.
Grant roles (`AgentUserGrant.role`, #309): `view` (the default; see, open, chat) or `manage`. `_owner_or_operator_or_403(agent, request, *, managers=True)` passes operator, owner, or a `manage` grantee (`_holds_manage_grant` opens its own session from `app.state.session_factory`, so the gate keeps its two-argument call shape and MCP's `require_owner_or_operator` inherits the widening); the grants routes call it with `managers=False`, so only the owner or an operator adds, changes (re-POST with the other role) or removes a grant. `_decider_or_403` still widens by any grant. A `manage` grant never reaches `_operator_block` (destroy) or any other operator-only gate. Resolver returns None (Okta down) → owned ∪ granted ∪ commons, and the response flags `groups_unavailable`. The room-wide colleagues routes narrow cabal's conversation log the same way (#192, #209): `_sees_every_agent(request)` is the IAP-off / admin / reader / no-resolver arm; otherwise `_colleague_scope(session, request)` is the caller's visible agent names (None = every row) and `_in_colleague_scope(row, scope)` keeps a row whose `target_agent` or `caller_agent: agent:<name>` is in it; a person's chat follows the agent it was with.
INVARIANTS:
- Authorization reads only the VERIFIED email (`iap_email` from IapMiddleware, or `sub` from a verified kobo JWT). Never trust a header or body field for identity.
- "Not visible" and "does not exist" return the identical 404; MCP also collapses "visible but not yours" into NotFound (authz.py). WHY: status codes must not leak existence or ownership.
- Visibility is enforced in exactly one place, `_visible_agent_or_404`; agent-scoped routes resolve the caller's own agent through it. Don't add per-route checks. Four readers on the invite lane query `Agent` directly on purpose, because the a2a directory of bare names is deliberately global: `_agent_ref`, `_team_pairs`, `create_invite`'s target lookup, and `list_requestable_agents`' candidate list. Two more query it directly for their own reasons: `_invite_side_stand_in` (a vanished agent becomes an ownerless stand-in, so only an operator can act on it) and `_add_thread_participant` (it checks consent between participants). Don't route any of the six through the visibility filter.
- Fail closed on the directory: an Okta outage removes group-derived visibility and group-based admin; it never widens. Grants and the commons survive (they are kobo DB rows, not Okta's).
- Agent-to-agent consent (kobo#310, gate 1): two agents may be a dispatch pair, and share a thread, through exactly three sources, all computed by `kobo_api.pairs.allowed_pairs` and read in main.py only through `_allowed_pairs` (`list_pairs`, `list_requestable_agents`, `_thread_consented` via `paired_either_way`): the same non-shared group (implicit, both directions), an accepted `A2AInvite` (one direction), and, with the permission service on, an `a2a_ask` grant the asker holds on the target's `agents` integration (one direction; requested by the asker's owner through `POST /api/agents/{asker}/access/requests` {integration: <target>, permissions: ["a2a_ask"]}, which applies `create_invite`'s own two refusals (self, already same group) and puts the target's integration first; approved by a room admin in Review; revoked by a room admin). The Access tab sends the grant request when `GET /api/agents/{name}/access` answers and the invite otherwise. Don't add a fourth source or a per-route re-implementation.
- Legacy agents with no `created_by` are operator-only to mutate.
- Destroy, convert, admin resync, repo-access decisions, and group moves are operator (`_is_admin`) only; a `manage` grant does not widen them. Teach and chat are open to any caller who can see the agent. `_convert_operator_block` must stay equal to `_operator_block` because the UI reads `destroy_visible` to offer convert (a test pins this).
- Readers (`config.reader_groups`, raw Okta names) see everything and mutate nothing.
- `/mcp` is mounted and the `mcp` SDK imported only when `config.mcp_enabled` (`mcp.oauth_client_id` set; workspace domain and issuer URL then required by validators).
- Escape hatch: `iap_audience` unset ⇒ every gate allows ("the room trusts its perimeter only when it has one"). Empty `operators` AND `admin_groups` ⇒ four operator gates are open (`_operator_block`, `_admin_operator_block`, `_convert_operator_block`, `_repo_access_operator_block`). Not the group move (it requires `_is_admin` whenever `iap_audience` is set, with no empty-list bypass) and not `_slack_operator_block`, which is keyed on its own list, `slack_operators`.
CONSUMERS: every route in api/kobo_api/main.py; api/kobo_api/mcp/tools/read.py + write.py (via authz.py); api/kobo_api/mcp/server.py `_KoboTokenVerifier`; tests: test_auth.py (IAP, the OAuth server, MCP JWTs, broker tokens), test_gates.py (every route gate, once, over a route table), test_access.py (visibility, grants, consent, thread privacy).
GOTCHA: the IAP-off escape hatch also applies to MCP callers, because `room_request` goes through the same gates. A room with MCP enabled but `iap_audience` unset gives every signed-in Workspace user full visibility and owner rights over every agent (read from code, not tested live).
