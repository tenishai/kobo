# switchboard — kobo ↔ cabal: directory, relay, colleague passes, dispatch policy

WHAT / SEAM: `CabalClient` (clients.py, l.~4052) speaks cabal's admin API with the operator bearer `CABAL_OPERATOR_TOKEN` (env, read live, never an org.yaml key). kobo is the POLICY OWNER; cabal stores and enforces a flat set. Policy computation: pairs.py `implicitly_paired`, `allowed_pairs` (+ its halves `invite_pairs`, `grant_pairs`, and `paired_either_way` for thread consent), `sync_dispatch_pairs`, `sync_dispatch_pairs_best_effort`. Wrappers: directory.py `sync_directory`/`retire_directory`/`sweep_directory`, colleagues.py `deliver_pass`. On/off: `cabal_enabled(config)` = `cabal_url` AND `agent_endpoint_template` AND the env token; also check `clients.cabal is not None`. Off, the gated routes answer 409 `_SWITCHBOARD_NOT_CONFIGURED` (main.py), which names those three settings (issue #123).
OPS / FLOW (cabal endpoints):
- `POST /admin/persona/{name}/graduate` {endpoint, audience=name, agent_card_json} — DirectoryStep; the card is read verbatim from the agent repo clone, never recomposed. `POST .../absorb` on destroy (404 tolerated).
- `GET /admin/agents` — the directory sweep (issue #274; nightly and REAL since 2026-10-31 from learnings.py `_directory_sweep`, audited as `directory.sweep` by the room; the Admin > Services button and its routes are gone): `directory.sweep_directory` keeps every active entry with an agent row of that name (any state; a row exists until forget), retires (absorbs) an entry with no row ONLY when it carries the room's marker (`room_registered`: `kind == federated` AND `endpoint == agent_endpoint_template.format(name)`; the card body is not readable back, so the endpoint is the marker) AND `kubectl.deployment_exists(name, name)` is False (a hand-built agent deployed as `<name>/<name>` has the same endpoint shape and no row; it lands in `live`, never touched), and lists the rest as `unknown`, never touched. A cluster that cannot be asked (or no kubectl) retires nothing: every row-less entry goes to `unknown` with `note` = `CLUSTER_SILENT_NOTE`, and the probe runs before any absorb. Dry run by default; the nightly pass (`learnings._directory_dry_run`) only logs leftovers at WARNING; retiring is the operator's click at `POST /api/admin/directory/sweep` (preview `GET`, both behind `_admin_panel_gate`, audit event `directory.sweep`). `_destroy_directory` FAILS the step with `DIRECTORY_RETIRE_MISSED_ERROR` when absorb did not land (issue #291, since 2026-10-29): the agent stays in the room as `destroy_failed` and Destroy again retries; only an unconfigured switchboard completes with a note. The sweep remains the cleanup for entries left by earlier destroys.
- `POST /admin/token/revoke` {sub: agent:<name>} THEN `POST /admin/token/mint-service` {sub: agent:<name>, scope:["colleague"], aud:"cabal-core", ttl_days:365} — `deliver_pass` in WireStep; token lands as Secret `<name>-cabal`, key `CABAL_COLLEAGUE_TOKEN` (via sero when configured, else `kubectl.apply_secret`).
- `POST /a2a/tasks` {target, task} (180s timeout): every room chat, teach (`_build_teach_envelope`), learnings sweep, hello, roster refresh, threads (one relay per addressed participant; a failed relay is that agent's `didn't answer` entry, never a failed turn, since 2026-10-28). When the switchboard is off, hello and chat fall back to the direct path (`clients.agent`) and DirectoryStep is a no-op.
- `PUT /admin/dispatch-pairs` {pairs:[[caller,target],...]} → {count}.
- `GET /admin/conversations[?limit,target,caller]`, `GET /admin/conversations/{task_id}`, `GET /admin/events/stream` (SSE, async client) — the colleagues feed. kobo filters what it relays per caller with `main._colleague_scope`/`_in_colleague_scope` (see the access-control card); cabal's log is room-wide and never consulted for who may read it.
INVARIANTS:
- Pair shape is `("agent:<caller>", "<target>")`: caller prefixed, target bare. Directional; an accepted `A2AInvite` adds exactly one direction, and so does a grant (kobo#310, gate 1, since 2026-10-30): with the permission service on, `allowed_pairs(session, config, bab, actor)` adds `(agent:asker, target)` for every name `bab.talks_to(asker)` returns (an active `a2a_ask` grant on the target's `agents` integration) when both are READY built agents. A bab `ClientError` is raised, never folded into a narrower set: `sync_dispatch_pairs_best_effort` and the operator resync swallow it and push NOTHING, so the switchboard keeps the last set; main.py's readers (`_allowed_pairs`) fall back to rows alone. One `talks_to` call per READY asker per sync.
- Implicit pairs: same non-null `group_name` on both sides AND not `SHARED_GROUP`. WHY: the commons is visible to everyone but its wiring stays consent-based. Group-less agents never pair. Only READY, non-connected agents appear, as caller or target.
- EMPTY pair set = WIDE OPEN in cabal (D-018). kobo never sends one: when nothing is allowed, `put_dispatch_pairs` sends `DENY_ALL_PAIR` (`("kobo:deny-all", "kobo:deny-all")`) and logs a WARNING every time, reporting count 0 (issue #194). WHY the sentinel is safe: cabal checks nothing but "two strings", so the guarantee is kobo's: colleague subs are only `agent:<name>` and agent names follow NAME_RE, which has no ':'. Never send `[]` and never add "skip if empty" (a skipped revoke-all leaves old pairs live).
- `sync_dispatch_pairs` holds `_SYNC_LOCK` (pairs.py) across compute and PUT, so in one process the last push carries the newest set. It does not order pushes from different processes (`api` + `worker` roles, replicas); there the next trigger heals a stale set.
- Every push sends the FULL current set, recomputed from DB rows. WHY: that is the reconciliation story; a lost push heals on the next trigger. Triggers: READY flip (provisioner.py), invite accept/revoke, a Review approval (`POST /api/admin/access/decide`, any approved result) and an admin's grant revoke (`DELETE /api/agents/{name}/access/grants/{id}`) since kobo#310, convert-to-connected and a group move (main.py; the metadata route pushes when `group_name` changed), destroy forget step (destroy.py; a wired miss is named in the step's note, issue #291), process boot (`_boot_sync_dispatch_pairs`), operator `POST /api/admin/sync-pairs` (raising core, so the operator sees failure). All others use `_best_effort` (swallows `CabalError`/`httpx.HTTPError`; state already committed).
- Revoke BEFORE mint on every re-wire (2026-09-24). WHY: cabal refuses tokens issued before the cutoff; minting first would let the new pass fall to its own revocation. A revoke failure stops the step before minting.
- Minted `scope` is always `["colleague"]`, never `operator`. Tokens and response bodies never appear in raised messages.
- `list_conversations` without `limit` is cabal's default 50 rows, clamped at 200, not unbounded.
- `GET /api/colleagues/feed` releases its DB session right after the visibility check and shares one fan-out across concurrent callers (`_coalesced` in main.py). WHY: on 2026-10-01 the feed held its connection through up to 400 serial switchboard calls per open tab, exhausted the pool, failed an unrelated agent's build step and got both replicas probe-killed. Keep the DB out of the fan-out.
- `/broker` accepts the same colleague JWT (aud `cabal-core`) verified against cabal's JWKS (pr_broker.py `verify_agent_token`); confused-deputy tradeoff accepted and documented there.
CONSUMERS: api/kobo_api/steps.py (WireStep, DirectoryStep, HelloStep, `_deliver_knowledge_refresh`), provisioner.py, destroy.py, learnings.py, main.py (chat, teach, threads, invites, colleagues feed/stream, admin resync; `_sync_directory_best_effort` after metadata, skill and runtime changes and, via `_directory_resync`, after any fast-lane commit that moved `FROM`), mcp/tools/read.py (conversation feed), composer.py (bakes cabal JWKS/issuer/audience into agent.yaml). Cross-repo: cabal's admin API (the cabal repo) is the other side; daedalus runtime reads `CABAL_COLLEAGUE_TOKEN` via `tools.colleagues.token_env`.
API: see endpoints above; kobo-side `allowed_pairs(session, config) -> set[tuple[str,str]]`, `sync_dispatch_pairs_best_effort(clients, config, session) -> int | None`, `CabalClient.dispatch_pairs_dirty`.
