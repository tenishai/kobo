# platform-clients — one Protocol per outside system, one real impl, one fake

WHAT / SEAM: api/kobo_api/clients.py. The outside systems in the table below are reached through a `typing.Protocol` (cabal is a concrete class), and code depends on the Protocol, never the backend. Four outside calls do NOT: they use httpx directly, are not in `Clients`, and have no fake in tests/fakes.py: mcp/oauth_as.py (Google token exchange), iap.py (JWKS fetch), github_app.py (installation token), bootstrap.py (catalog refresh POST). The `Clients` dataclass (l.~5593) is the bag handed to steps and routes (`app.state.clients`, `Ctx.clients`).

OPS / FLOW: `Clients.real(config)` is called once per process in `main.build_default_app`; tests build `Clients(...)` from fakes and pass it to `create_app`. `CommandRunner.run()` raises `ClientError` on non-zero exit; callers that tolerate one failure catch it and inspect `.stderr` (e.g. `_gh_returned_404`). GitHub auth: a GitHub App installation token (`installation_token_provider`, github_app.py) passed as `GH_TOKEN` in the subprocess env when the App is configured, else the ambient `gh auth` session. Vertex/GCS tokens come from `CachedGcloudToken` (metadata server, then `gcloud` CLI fallback).
INVARIANTS:
- `KubectlClient.restart_deploy(..., annotations=)` writes the caller's pod-template annotations beside `rollout restart`'s own stamp (`RESTARTED_AT_ANNOTATION`) in one merge patch, so it is still one roll; without them it is `rollout restart`. A delivery names its commit this way (`delivery.BUNDLE_COMMIT_ANNOTATION`), and `FakeKubectl` keeps what a restart named in `template_annotations`, read back by `deployment_status_json`. `GitHubClient.includes(repo, tip, commit)` answers whether `tip` carries `commit` from GitHub's compare status, with no clone (`FakeGitHub` reads `ancestor_pairs`).
- `VertexImageClient.generate` raises `ImageRefused` (a `ClientError`) when the model answers and declines (no candidate, or no picture in it), so `avatars.paint_portrait` asks again in other words; every other failure is a plain `ClientError` and is not asked twice.
- slack, cabal, groups, people_search, sero and models_gateway are None when unconfigured, and None means "feature off" (`models_gateway` is built only when `models_gateway_url` is set, kobo#390; `model_providers.gateway_on(config)` is the switch and the field is the door). Check for None; never construct a client ad hoc in a route. `slack` stays the DEPLOYMENT client only (None when neither `slack_tokens_*` key is set, whatever namespace the process runs in; tests/test_clients.py pins this); the Slack connection's pair (issue #284, a connection row since kobo#377) is resolved per request by `room_credentials.slack_client(clients)` (the connection first, then `clients.slack`), so gates and the destroy step call that, never `clients.slack` directly. `image`, `name` and `storage` are always built by `Clients.real`; their None default exists only so older test constructions of `Clients(...)` keep working.
- Never put a token or secret value in a raised message or log. WHY: raised messages can reach route responses. `CabalClient` and `HttpxStorageClient` go further and keep response bodies out of raised messages (logged truncated, `resp.text[:200]`); `HttpxGojiraClient` does NOT (its `ClientError` includes `resp.text`), so don't copy it for a client whose responses may echo secrets.
- A new external call gets a Protocol method + a fake method in tests/fakes.py in the same change; the fakes mirror P0-observed backend behavior (e.g. gojira's generated kustomization) so step tests mean something.
- `GojiraConflict` (409 on create) is distinct from `ClientError` so onboard can decide whether the app is its own.
- `GojiraClient.create_app(..., seed=None)` (2026-11-14): the caller's share of the platform's first setup PR, `{needs, base_files, note}`; sent only when given, so an older platform sees the body it always did. The platform refuses a seed together with `auto_merge_setup_pr`, a key outside the ones a pod reads, and a name its written contract would read back differently. A 422 to a call that carried a seed is asked again without it: the seed saves a pull request and is never a condition of connecting. `FakeGojira.create_app_calls` records it.
- `GojiraClient.create_app(..., handed_over=False)` and `reprovision(app_id, *, handed_over=False)` (2026-11-16): the room's statement that a connected repository's deploy files were handed to the platform, which then merges its own setup pull request, seed included. Sent only when true (reprovision sends no body otherwise), so an older platform sees what it always did: it ignores the field on create, still answers 422 to a seed beside auto-merge (asked again without the seed), and its status carries no `handed_over` key. `FakeGojira.handed_over_calls` records the app ids; `FakeGitHub.merge_pr` closes the request it merged.
CONSUMERS: api/kobo_api/steps.py, provisioner.py, health.py (ready agents probed once a minute; verdict kept in memory per replica), destroy.py, main.py (routes), directory.py, colleagues.py, pairs.py, learnings.py, knowledge.py, slack_setup.py, agent_env.py, mcp/tools/*.py; api/tests/* via tests/fakes.py.

2026-11-16: `GitHubClient.runs_for_commit` carries each run's `updated_at` (gh `updatedAt`) and `workflow` (gh `workflowName`), which `BuildStep` compares with the agent's creation; `FakeGitHub` runs without it count as fresh.

2026-10-12: `GhCLI.repo_exists` reads `gh api repos/{repo}` and compares the `full_name` GitHub answers with; a name GitHub only redirects (a destroyed agent's repo, renamed to `archived-agent-<name>-<id>`) counts as free.
- `CabalClient.mint_service` (2026-10-24): the generic switchboard mint behind the room's own gateway admin token (`kobo_api.liminal_admin.RoomAdminToken`: sub and persona `kobo-room`, aud `liminal`, `admin:*`). `Clients.liminal_admin` is that admin-plane client, typed loosely to keep `liminal_admin` importing this module and not the reverse.
- `CabalClient.put_dispatch_pairs` (2026-10-24, issue #194): never sends an empty set; an empty policy goes out as `DENY_ALL_PAIR` (see switchboard).
- `gsa_absent(stderr)` (2026-11-04): what a failed `service-accounts describe` means. NOT_FOUND is a never-existing account; PERMISSION_DENIED "on resource (or it may not exist)" is a soft-deleted one (thirty days after a destroy, answered that way even to a project owner). `GcloudClient.ensure_gsa` creates on either (Google allows a new account under a deleted one's name: a new identity), and says "deleted recently, retry or pick another name" when create still collides; `delete_gsa` treats a soft-deleted account as already gone. Before this a recreate under a destroyed name failed its Access step.
- `KubectlClient.namespace_created_at` (2026-10-24, issue #193): a namespace's creation time as naive UTC, None when absent, `ClientError` when the cluster cannot be asked. Create and connect refuse a name whose namespace exists; destroy keeps the namespace, the stored secrets and the `agent-<name>` GSA of an agent whose namespace is older than its row. `FakeKubectl(namespaces={name: created_at}, namespace_error=...)` seeds it.
- `KubectlClient.namespace_deleting` (2026-11-20): True when the namespace exists and is being deleted (`--ignore-not-found -o jsonpath={.metadata.deletionTimestamp}`), `ClientError` when the cluster cannot be asked. `main._namespace_in_the_way` asks it after `namespace_created_at`, for create, connect and the connect scan: a destroyed agent's namespace still being cleared is `code: name_clearing` (a wait, "try again in a minute"), any other existing namespace `code: namespace_in_use`; an agent row holding the name is `code: name_taken`. The 409 carries the code and the scan reports the first two as blockers. `FakeKubectl(namespaces_deleting={name})` seeds it; the name must be in `namespaces` too.

`FakeCabal.relay` takes per-agent overrides (`relay_results`, `relay_errors`) since 2026-10-28, because a thread turn relays to several agents in one call and the tests need one to fail while another answers.
- `Clients.bab` (object | None): the room's permission service, `kobo_api.bab.BabClient` (Protocol) / `HttpxBabClient` / `tests.fakes.FakeBab`; built in `main.build_default_app` by `build_bab(config)` from `bab_url` + env `KOBO_BAB_TOKEN`, like `liminal_admin`. Console token + `X-Bab-Actor` per call; `ClientError` carries bab's `detail` sentence, never the token. Vendor probes before a connect: `probe_aws`, `probe_datadog`, `probe_github` (2026-10-31, kobo#338: `POST /probe/github`, the installation id as the generic probe's `role_arn`; the fake refuses ids ending in 999 and answers `not configured` for ones ending in 998). The room pushes its topology (`push_topology`) at boot, after create and destroy, and from Review › Sync agents (2026-10-29); the same push makes every READY built agent an `agents` integration (`ensure_agent_integrations`: `PUT /integrations/{agent}` {vendor "agents", spec {name}, ceiling ["a2a_ask"]} for each one bab lacks), destroy deletes it and everything else the agent held (`remove_agent`: `DELETE /agents/{agent}` after the push that dropped it, bab 0.4.23, kobo#476: its repository set, grants, waiting requests and leases, with a set another agent still holds a level on reported in `kept`; `remove_agent_integration` alone when the push missed or the service has no such route), and `talks_to(asker, actor)` reads `GET /agents/{asker}/talks-to` → `talks_to` (kobo#310, 2026-10-30). The fake's catalogue carries the `agents` vendor (group "Colleagues", `a2a_ask`, tier read) and answers `talks_to` from its own active grants. AWS organizations (kobo #275): `external_id_for_org(org)` is one HMAC-derived external id per organization, and `discover_accounts(org, actor, role_name)` asks bab which member accounts carry the spoke role; `admin_integrations.register_accounts` connects those (a row here, an account under the org in bab) at hub connect time and from `POST /api/admin/integrations/{org}/accounts/check`. The fake's `reachable_accounts` says which accounts answer. `probe_datadog(service_account_id, actor)` (kobo#322, 2026-10-30) is `POST /probe/datadog` with the id under both `service_account_id` and `role_arn`: bab creates and deletes a `bab-probe` application key with the keys the room wrote to the Secret `bab-datadog` in `bab_namespace` (`admin_integrations._connect_datadog`, through `KubectlClient.apply_secret`/`delete_secret`). The fake records ids in `datadog_probes`; an id containing "refuse" is turned down, one containing "unconfigured" answers "not configured". GitHub per agent (kobo#365, bab 0.4.12, 2026-11-01): `put_integration(..., parent=<connection>)` hangs a child under a service connection as well as under an AWS organization (kind `account`, one level); the listing carries each row's `spec`; every catalogue permission carries a `label` (the fake's `github` vendor: `github_repos_read` Read, `github_pulls_review` Review pull requests, `github_pulls_write` Open pull requests); `delete_integration` of a connection takes its children and their grants with it. `kobo_api.github_access` is the room's side (connection, child `<connection>-<agent>`, `write_child`, `migrate_repo_access`); `bab.picker(bab, actor, agent=...)` shows the agent's child or the connection as a placeholder, with `repositories` and `has_repo_set` on every account, and `tool` on every permission (kobo#474, 2026-11-13: `gateway_lane.Lanes.opens_tool` through `picker(..., lanes=)`, false for a permission no room target and no tool on the gateway's handler cards serves, which the Access tab greys as "no tool uses this yet"; since #524 a handler's tools name their own permissions on its card and `TARGET_TOOLED` keeps Datadog's hosted server's set); `bab.all_permissions` is a GitHub connection's ceiling. `put_integration` passes a 202 body through (bab 0.4.22: an owner's addition to a granted set answers `{repositories, pending}`); the fake's `reviewers` (None = everyone reviews) turns on those rules: a non-reviewer may write a child's non-empty set, an addition to a set with active grants or a pending level request becomes one pending request of kind `repositories` with `proposal {added, removed}`, any whole write withdraws it, and `decide` applies it (2026-11-12). A child may instead be every repository (`spec.all_repositories`, bab 0.4.26): the fake refuses a level beyond the read tier on it, refuses it for a set holding or awaiting more, says `all_repositories` back on a write, and a non-reviewer widening a held set to it gets one pending `repositories` request with `proposal.all` that `decide` applies. With `reviewers` set, `decide` refuses anyone else, except the room actor approving its own Read request on an agent's own set (`room_decides`, False = a service older than 0.4.23); `delete_agent` mirrors the service's route (refused while the last pushed topology lists the agent; `agent_route` False answers `Not Found`; `agents_removed` records calls) (2026-11-13). Google Cloud (kobo#390, 2026-11-02): `identity(vendor, actor)` is `GET /identity/{vendor}` and `probe(vendor, actor, **body)` is `POST /probe/{vendor}`, with `aws_identity`/`probe_aws` kept as thin wrappers; `discover_accounts(org, actor, role_name=None)` sends an empty body for a Google Cloud folder or organization (a row whose spec carries `parent_resource`, kind `org`). - `Clients.room_services` (object | None, 2026-10-29, issue #284; the store behind the Slack and GitHub connection rows since kobo#377, read only through `kobo_api.room_credentials`): `kobo_api.room_services.RoomServices`, the room's own credentials store (Slack config-token pair, GitHub app for pull requests) as one Secret per vendor in `room_namespace` (or the pod's own); None when the room has neither. Built in `Clients.real` by `build_room_services` from config and the pod's own namespace file ONLY (never kubectl's context, never a kubectl call: a self-hosted CI runner is a pod, and construction must not shell out). Whether the room HOLDS anything is asked at request time. `probe_slack_token_store` also dry-runs the room-held pair's write at boot. The secrets platform (sero) is NOT used for these: it has no read-back lane and the room needs the values back.
- `KubectlClient.set_env(namespace, deploy, name, value)` (2026-11-01): one environment variable set on the live Deployment (`kubectl set env deployment/<deploy> NAME=value`), which rolls the pods itself; no separate `restart_deploy`. The Slack wake route (`main.set_slack_wake`, `PUT /api/agents/{name}/slack/wake`) calls it right after `agent_env.edit_gojira_yaml` commits the same `SLACK_WAKE_MODE` value, so the running agent restarts with the choice now and the provisioner's later apply changes nothing; a `ClientError` is logged and answered as `applied_now: false` on a 200, never a 5xx, because the commit already landed. The ClusterRole in `k8s/cluster/rbac.yaml` already grants `get, patch` on deployments, which is all `set env` needs. `FakeKubectl(set_env_error=...)` refuses; `FakeKubectl.env_sets` records `(namespace, deploy, name, value)`. `unset_env(namespace, deploy, name)` (2026-11-13) is the other half (`kubectl set env deployment/<deploy> NAME-`): the same route calls it when the emoji that wake an agent are cleared, because `SLACK_WAKE_EMOJI` is then removed from gojira.yaml, not set to nothing; a variable that was never there is a success. The fake records `env_unsets` and refuses on the same `set_env_error`.
- `Clients.models_gateway` (kobo#390, 2026-11-02): the room's model gateway. Mint returns the key and the caller delivers it (`model_providers.deliver_models_key`, Secret `<agent>-models`, key `MODELS_GATEWAY_KEY`, through sero when wired else `apply_secret`); revoke is by alias `agent:<name>` so the room never holds a key to take it back. Refusals carry `resp.text[:300]`, which is safe because no request of ours carries a key except the mint's answer, which is never in a raised message.
- `GcloudClient.workload_principal(namespace, ksa)` (2026-11-24) is the `principal://` name IAM knows a Kubernetes service account by when it is granted with no Google account between; it needs the project's number (`Config.gcp_project_number`, or one `projects describe`). The bucket and model methods take it wherever they take an email (`iam_member`). `allow_token_creator` grants Token Creator on one account, never on the project. Both exist for agents whose pod does not run as its Google account (`kobo_api.cloud_identity`).
- `GcloudClient.grant_bucket_prefix_write` (2026-11-06) waits out IAM propagation for a new account (`BUCKET_BINDING_PAUSES_S`, only on "Service account ... does not exist"); `revoke_bucket_prefix_write` takes both bindings back and destroy calls it BEFORE `delete_gsa` (a deleted account's bindings linger as `deleted:` members).
- `FakeCloud.revoke_bucket_prefix_write` (2026-11-06) records the call and answers True, so destroy tests can pin that it runs before `delete_gsa`.
- `NameClient.draft(job, rules)` (2026-11-17): the one persona-writing call. It returns `name`, `who_they_are`, `what_they_do`, `rules` and `purpose_tags`, with the body in the built-ins' shape, from a sentence or a pasted document alike, unchecked. `NameClient.distill` and `FakeName`'s distill half are gone with the paste-as-is path. A document keeps its length: the 25 to 45 lines and eight to twelve rules are for a short description, while a document's working detail is carried whole under bold labels (up to 120 lines) with every rule it states (up to forty). The call runs with thinking off and its own 90s timeout (`_PERSONA_DRAFT_TIMEOUT`), under the front door's 120s. The draft route is the only caller: it hands the reply (or None on `ClientError`) to `persona_draft.finalize_draft`, which checks each field and falls back on its own for any that fails.
