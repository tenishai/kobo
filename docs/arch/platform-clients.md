# platform-clients — one Protocol per outside system, one real impl, one fake

WHAT / SEAM: api/kobo_api/clients.py. The outside systems in the table below are reached through a `typing.Protocol` (cabal is a concrete class), and code depends on the Protocol, never the backend. Six outside calls do NOT: they use httpx directly, are not in `Clients`, and have no fake in tests/fakes.py: pr_broker.py (GitHub App token mint), jira_broker.py (Jira GET), mcp/oauth_as.py (Google token exchange), iap.py (JWKS fetch), github_app.py (installation token), bootstrap.py (catalog refresh POST). The `Clients` dataclass (l.~4782) is the bag handed to steps and routes (`app.state.clients`, `Ctx.clients`).

OPS / FLOW: `Clients.real(config)` is called once per process in `main.build_default_app`; tests build `Clients(...)` from fakes and pass it to `create_app`. `CommandRunner.run()` raises `ClientError` on non-zero exit; callers that tolerate one failure catch it and inspect `.stderr` (e.g. `_gh_returned_404`). GitHub auth: a GitHub App installation token (`installation_token_provider`, github_app.py) passed as `GH_TOKEN` in the subprocess env when the App is configured, else the ambient `gh auth` session. Vertex/GCS tokens come from `CachedGcloudToken` (metadata server, then `gcloud` CLI fallback).
INVARIANTS:
- slack, cabal, groups, people_search and sero are None when unconfigured, and None means "feature off". Check for None; never construct a client ad hoc in a route. `slack` stays the DEPLOYMENT client only (None when neither `slack_tokens_*` key is set, whatever namespace the process runs in; tests/test_clients.py pins this); the room-held pair (issue #284) is resolved per request by `room_services.slack_client(clients)` (room first, then `clients.slack`), so gates and the destroy step call that, never `clients.slack` directly. `image`, `name` and `storage` are always built by `Clients.real`; their None default exists only so older test constructions of `Clients(...)` keep working.
- Never put a token or secret value in a raised message or log. WHY: raised messages can reach route responses. `CabalClient` and `HttpxStorageClient` go further and keep response bodies out of raised messages (logged truncated, `resp.text[:200]`); `HttpxGojiraClient` does NOT (its `ClientError` includes `resp.text`), so don't copy it for a client whose responses may echo secrets.
- A new external call gets a Protocol method + a fake method in tests/fakes.py in the same change; the fakes mirror P0-observed backend behavior (e.g. gojira's generated kustomization) so step tests mean something.
- `GojiraConflict` (409 on create) is distinct from `ClientError` so onboard can decide whether the app is its own.
CONSUMERS: api/kobo_api/steps.py, provisioner.py, health.py (ready agents probed once a minute; verdict kept in memory per replica), destroy.py, main.py (routes), directory.py, colleagues.py, pairs.py, learnings.py, knowledge.py, slack_setup.py, agent_env.py, mcp/tools/*.py; api/tests/* via tests/fakes.py.
API: `Clients.real(config)`; `cabal_enabled(config)`; `installation_token_provider(config)`; `probe_slack_token_store(clients)` (boot write-probe of the Slack token Secret); `gsa_email(name, project)`; errors `ClientError`, `GojiraConflict`, `SlackApiError`, `StorageNotFound`, `CabalError`; value type `SlackAppCredentials`.

2026-10-12: `GhCLI.repo_exists` reads `gh api repos/{repo}` and compares the `full_name` GitHub answers with; a name GitHub only redirects (a destroyed agent's repo, renamed to `archived-agent-<name>-<id>`) counts as free.
- `CabalClient.mint_service` (2026-10-24): the generic switchboard mint behind the room's own gateway admin token (`kobo_api.liminal_admin.RoomAdminToken`: sub and persona `kobo-room`, aud `liminal`, `admin:*`). `Clients.liminal_admin` is that admin-plane client, typed loosely to keep `liminal_admin` importing this module and not the reverse.
- `CabalClient.put_dispatch_pairs` (2026-10-24, issue #194): never sends an empty set; an empty policy goes out as `DENY_ALL_PAIR` (see switchboard).
- `KubectlClient.namespace_created_at` (2026-10-24, issue #193): a namespace's creation time as naive UTC, None when absent, `ClientError` when the cluster cannot be asked. Create and connect refuse a name whose namespace exists; destroy keeps the namespace, the stored secrets and the `agent-<name>` GSA of an agent whose namespace is older than its row. `FakeKubectl(namespaces={name: created_at}, namespace_error=...)` seeds it.

`FakeCabal.relay` takes per-agent overrides (`relay_results`, `relay_errors`) since 2026-10-28, because a thread turn relays to several agents in one call and the tests need one to fail while another answers.
- `Clients.bab` (object | None): the room's permission service, `kobo_api.bab.BabClient` (Protocol) / `HttpxBabClient` / `tests.fakes.FakeBab`; built in `main.build_default_app` by `build_bab(config)` from `bab_url` + env `KOBO_BAB_TOKEN`, like `liminal_admin`. Console token + `X-Bab-Actor` per call; `ClientError` carries bab's `detail` sentence, never the token. Vendor probes before a connect: `probe_aws`, `probe_datadog`, `probe_github` (2026-10-31, kobo#338: `POST /probe/github`, the installation id as the generic probe's `role_arn`; the fake refuses ids ending in 999 and answers `not configured` for ones ending in 998). The room pushes its topology (`push_topology`) at boot, after create and destroy, and from Review › Sync agents (2026-10-29); the same push makes every READY built agent an `agents` integration (`ensure_agent_integrations`: `PUT /integrations/{agent}` {vendor "agents", spec {name}, ceiling ["a2a_ask"]} for each one bab lacks), destroy deletes it (`remove_agent_integration`), and `talks_to(asker, actor)` reads `GET /agents/{asker}/talks-to` → `talks_to` (kobo#310, 2026-10-30). The fake's catalogue carries the `agents` vendor (group "Colleagues", `a2a_ask`, tier read) and answers `talks_to` from its own active grants. AWS organizations (kobo #275): `external_id_for_org(org)` is one HMAC-derived external id per organization, and `discover_accounts(org, actor, role_name)` asks bab which member accounts carry the spoke role; `admin_integrations.register_accounts` connects those (a row here, an account under the org in bab) at hub connect time and from `POST /api/admin/integrations/{org}/accounts/check`. The fake's `reachable_accounts` says which accounts answer. `probe_datadog(service_account_id, actor)` (kobo#322, 2026-10-30) is `POST /probe/datadog` with the id under both `service_account_id` and `role_arn`: bab creates and deletes a `bab-probe` application key with the keys the room wrote to the Secret `bab-datadog` in `bab_namespace` (`admin_integrations._connect_datadog`, through `KubectlClient.apply_secret`/`delete_secret`). The fake records ids in `datadog_probes`; an id containing "refuse" is turned down, one containing "unconfigured" answers "not configured". GitHub per agent (kobo#365, bab 0.4.12, 2026-11-01): `put_integration(..., parent=<connection>)` hangs a child under a service connection as well as under an AWS organization (kind `account`, one level); the listing carries each row's `spec`; every catalogue permission carries a `label` (the fake's `github` vendor: `github_repos_read` Read, `github_pulls_review` Review pull requests, `github_pulls_write` Open pull requests); `delete_integration` of a connection takes its children and their grants with it. `kobo_api.github_access` is the room's side (connection, child `<connection>-<agent>`, `write_child`, `migrate_repo_access`); `bab.picker(bab, actor, agent=...)` shows the agent's child or the connection as a placeholder, with `repositories` and `has_repo_set` on every account; `bab.all_permissions` is a GitHub connection's ceiling. bab exposes no call to end an open lease (`github_access.LEASES_NOTE`). The Agents audit (kobo#371, 2026-11-01): `events(since, until, kinds, agent, limit, actor)` is bab `GET /events` (`kind` as one comma list, `agent` matches `detail.agent`); `kobo_api.audit_agents.page` merges it with `all_leases`/`leases` into audit rows for `GET /api/admin/audit/agents`, holding no database session. The fake keeps `_events` rows shaped like the service's.
- `CabalClient.list_agents` (2026-10-29, issue #274): `GET /admin/agents`, the switchboard's whole bulletin board with `status`, `kind` and `endpoint`; read by `directory.sweep_directory`. `FakeCabal(agents_result=[...], agents_error=...)` seeds it and counts calls in `list_agents_calls`.
- `KubectlClient.deployment_exists(namespace, deploy)` (2026-10-29, issue #274): True/False, or `ClientError` when the cluster cannot be asked (`--ignore-not-found -o name`, the `namespace_created_at` idiom), unlike `deployment_status_json` whose failure folds absent and unreachable together. `FakeKubectl(deployments={(ns, name)}, deployment_exists_error=...)` seeds it.
- `KubectlClient.delete_secret(namespace, name)` (2026-10-29, issue #284): the remove half of `apply_secret`, `--ignore-not-found`, for the room's own Secrets. `FakeKubectl.secrets_deleted` records it and the entry leaves `.secrets`.
- `Clients.room_services` (object | None, 2026-10-29, issue #284): `kobo_api.room_services.RoomServices`, the room's own credentials store (Slack config-token pair, GitHub app for pull requests) as one Secret per service in `room_namespace` (or the pod's own); None when the room has neither. Built in `Clients.real` by `build_room_services` from config and the pod's own namespace file ONLY (never kubectl's context, never a kubectl call: a self-hosted CI runner is a pod, and construction must not shell out). Whether the room HOLDS anything is asked at request time. `probe_slack_token_store` also dry-runs the room-held pair's write at boot. The secrets platform (sero) is NOT used for these: it has no read-back lane and the room needs the values back.
- `KubectlClient.set_env(namespace, deploy, name, value)` (2026-11-01): one environment variable set on the live Deployment (`kubectl set env deployment/<deploy> NAME=value`), which rolls the pods itself; no separate `restart_deploy`. The Slack wake route (`main.set_slack_wake`, `PUT /api/agents/{name}/slack/wake`) calls it right after `agent_env.edit_gojira_yaml` commits the same `SLACK_WAKE_MODE` value, so the running agent restarts with the choice now and the provisioner's later apply changes nothing; a `ClientError` is logged and answered as `applied_now: false` on a 200, never a 5xx, because the commit already landed. The ClusterRole in `k8s/cluster/rbac.yaml` already grants `get, patch` on deployments, which is all `set env` needs. `FakeKubectl(set_env_error=...)` refuses; `FakeKubectl.env_sets` records `(namespace, deploy, name, value)`.
